# GD32Flasher

Прошивка микроконтроллеров **GD32** (F3x0 / F1x0 и родственные) через **ST-Link V2** без консоли.
Внутри — портативный OpenOCD и GUI-обёртка над ним.

Появился после ремонта турникета ASR100 на GD32F330CBT6: STM32CubeProgrammer этот чип читает и стирает, но **записать не может** — виснет и падает по таймауту. OpenOCD прошивает с первого раза. Полный разбор случая: [docs/case-ASR100-GD32F330.md](docs/case-ASR100-GD32F330.md).

## Быстрый старт

1. Подключить ST-Link V2 к плате: **SWDIO, SWCLK, GND, 3.3V** (землю — отдельным проводом рядом с сигнальными).
2. Запустить **`GD32Flasher.bat`**.
3. Нажать **«Проверить связь»** — убедиться, что чип определился.
4. Нажать **«Считать дамп»** и сохранить его. **Делать всегда**, до любых изменений: если прошивки в исходном виде больше нигде нет, это единственный способ вернуть плату в рабочее состояние.
5. Выбрать файл прошивки через **«Обзор...»**.
6. Нажать **«Прошить + проверить»**.
7. Снять питание, отключить ST-Link, подать питание, проверить устройство.

При первом запуске GUI сам распакует OpenOCD в `%LOCALAPPDATA%\GD32Flasher` (несколько секунд). Устанавливать ничего не нужно.

## Кнопки

| Кнопка | Что делает |
|---|---|
| Проверить связь | `flash info 0` + первые слова Flash. Проверка контакта и состояния защиты |
| Считать дамп | Читает 128 КБ с `0x08000000` в выбранный файл |
| Стереть | Полное стирание (с подтверждением) |
| Прошить + проверить | Стирание нужных секторов → запись → `verify_image` → `reset run` |
| Только проверить | Сверяет содержимое Flash с файлом, ничего не пишет |

Галка **«Снимать резервный дамп»** (включена по умолчанию) перед стиранием и прошивкой автоматически сохраняет копию Flash в `%LOCALAPPDATA%\GD32Flasher\work\backup_<дата>.bin`. Если дамп снять не удалось — операция отменяется.

**SWD, кГц** — при нестабильной связи снижать до 480. Дефолтные 4000 у Cube для GD32 на проводах избыточны.

## Как понять, что всё прошло

OpenOCD **не печатает** `wrote ... bytes` и `verified ... bytes` при запуске цепочкой команд — это результат команды (`command_print`), а не лог. Молчание — норма. GUI определяет успех сам и пишет в конце `РЕЗУЛЬТАТ: успешно`. Критерий: ни одной строки `Error:` и выполнение дошло до `shutdown command invoked`.

Дополнительный признак живой прошивки в логе `reset halt`:

```
xPSR: 0x01000000 pc: 0x080000c8 msp: 0x20003828
```

`msp` и `pc` должны совпадать с первыми двумя словами образа (SP и reset vector минус thumb-бит). На пустом Flash было бы `msp = 0xFFFFFFFF`.

## Ручной режим (если GUI не подходит)

Из папки распакованного OpenOCD, PowerShell, одной строкой:

```powershell
.\bin\openocd.exe -f interface/stlink.cfg -f target/stm32f1x.cfg -c "adapter speed 950" -c "init; reset halt; flash write_image erase C:/fw/ASR100.bin 0x08000000; verify_image C:/fw/ASR100.bin 0x08000000; reset run; shutdown"
```

Интерактивно: запустить OpenOCD без цепочки `-c`, подключиться `telnet localhost 4444`, дальше `reset halt`, `flash info 0`, `stm32f1x options_read 0`, `dump_image dump.bin 0x08000000 0x20000`, `flash erase_sector 0 0 last`, `mdw 0x08000000 16`.

Снятие защиты (**делает mass erase — сначала дамп!**): `stm32f1x unlock 0`, затем **полностью обесточить плату** — option bytes применяются только по power-on reset, по NRST не применяются.

## Грабли

- **CubeProgrammer не пишет GD32F330.** Опознаёт его как STM32F103 Medium-density (`ID 0x410`, Cortex-M3, 20 КБ SRAM) и грузит в цель flash loader, который не помещается в реальные 16 КБ SRAM. Стирание проходит (ему буфер не нужен), запись виснет и падает через 61 с: `Error: failed to download Sector[0]`. Лечится не настройками, а сменой инструмента.
- **Кириллица в путях.** OpenOCD её не переваривает. GUI поэтому работает в `%LOCALAPPDATA%\GD32Flasher` и копирует туда прошивку перед записью. В ручном режиме держать файлы в `C:\fw\`.
- **Обратные слэши в аргументах `-c`.** Их разбирает Tcl: `C:\fw\file.bin` → `\f` = form feed, файл «не найден». Только прямые: `C:/fw/file.bin`.
- **PowerShell ≠ cmd.** Перенос строки в PS — backtick `` ` ``, а не `^`. Запуск из текущей папки — `.\bin\openocd.exe`.
- **`STM32 flash size failed, probe inaccurate - assuming 128k flash`** — норма для GD32, драйвер не знает его ID. Если мешает, объявить банк вручную: `flash bank gd.flash stm32f1x 0x08000000 0x20000 0 0 $_TARGETNAME`.
- **`Adding extra erase range`** — норма: конец образа не кратен странице 1 КБ.
- **Драйвер ST-Link.** OpenOCD ходит через libusb; драйвер от CubeProgrammer обычно подходит. Если `open failed` — Zadig/WinUSB, но тогда Cube перестанет видеть ST-Link, пока не вернуть драйвер.
- **Клоны ST-Link V2** часто не имеют выведенной линии NRST — «connect under reset» на них не работает.
- **Распаковка на сетевой диск (Z:) очень медленная** — тысячи мелких файлов скриптов, около 5 минут. GUI распаковывает локально, поэтому быстро.

## Если SWD не поддаётся вообще

Штатный UART-загрузчик GigaDevice (протокол тот же, что у ST — AN3155):
BOOT0 на VDD через 10 кОм, USB-UART на PA9 / PA10, шить `stm32flash`:

```
stm32flash.exe -w fw.bin -v -g 0x0 COM<N>
```

Загрузчик зашит производителем и про свою SRAM знает правильно — не зависит ни от каких внешних flash loader'ов.
