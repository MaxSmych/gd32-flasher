# AGENT_GUIDE — GD32Flasher

Единый источник правды по проекту. Главнее README при расхождении.
Обновлено: 2026-09-11.

## Что это

GUI поверх портативного OpenOCD для прошивки GD32/STM32 через ST-Link. Один файл на
PowerShell + WinForms, без установки. Появился из ремонта турникета ASR100 на
GD32F330CBT6, который STM32CubeProgrammer читает и стирает, но не пишет.

## Состав

```
GD32Flasher.bat     запуск (cd в свою папку, потом powershell -File по голому имени)
GD32Flasher.ps1     всё приложение: UI, локализация, сессия OpenOCD
diagnose.bat        отчёт на рабочий стол, если GUI не стартует
tools\...zip        портативный OpenOCD 0.12.0-7 + .sha
tools\stlink-driver\ оригинальный STSW-LINK009 v3 (подписанный, из CubeProgrammer):
                     stlink_winusb_install.bat от админа, ДО подключения ST-Link
docs\case-*.md      разбор случая с турникетом
```

Всё, кроме драйвера программатора, портативно: права администратора не нужны, установка
не требуется. Драйвер — единственное, что делается на новой машине один раз и с админом.

## Как устроено

- **Рабочая папка** — `%LOCALAPPDATA%\GD32Flasher` (если в пути кириллица — `C:\GD32Flasher`).
  Туда распаковывается OpenOCD при первом запуске, туда же копируется прошивка (`work\fw.bin`)
  и падают бэкапы `backup_<дата>.bin`.
- **Сессия** — постоянный процесс OpenOCD плюс telnet `127.0.0.1:4444`. Команды идут
  через `Ocd-Send`, обёртка с логированием и оценкой результата — `Ocd-Run`.
- **Два потока вывода.** Ответы команд приходят по telnet, а лог OpenOCD (`Info`,
  `Warn`, `Error`) — в перенаправленные stdout/stderr, которые дочитывает `Pump-Log`
  по таймеру 250 мс. Оценка результата смотрит в оба.
- **Автоопределение чипа** — `Find-Target`: ОДИН запуск, из вывода берётся `device id`,
  младшие 12 бит ищутся в `$script:IdTable` → конфиг (`Get-CfgByDeviceId`). Секунда
  вместо полуминуты. Перебор остался запасным путём и печатает по каждому кандидату,
  что тот ответил, но **`device id` главнее имени согласившегося конфига**: таблица
  применяется и к выводу кандидата в переборе. Имя конфига решает, только если `device
  id` не прочитался вовсе. Первый за сеанс запуск OpenOCD бывает пустым (холодный старт
  сразу после распаковки) — пустой вывод не ответ, делается один повтор.
- **Локализация** — словарь `$Str` (RU/EN) и `Apply-Language`; текст берётся через `T 'ключ'`.
  Новый текст в UI = новый ключ в ОБА словаря.
- **Завершение сессии** — одна точка, `Stop-Session`, с жёстким бюджетом времени:
  флаг `$script:closing` (глушит `Log` и выводит `Ocd-Send` из ожидания) → стоп таймера →
  `shutdown` в сокет БЕЗ чтения ответа → 200 мс → `Kill` + 1,5 с. По `shutdown` процесс
  не выходит (грабля 15), поэтому ждать нечего; живой замер закрытия — 43 мс.
  `Ocd-Disconnect` — обёртка над ней. Крестик спрашивает подтверждение только если
  `$script:busy`, то есть идёт операция с Flash.
- **Потеря программатора** — `Pump-Log` считает подряд идущие строки `$script:lostPattern`
  (`Fail reading CTRL/STAT`, `Polling failed`, `Examination failed`, `Force reconnect`,
  `open failed`); три подряд = сессия закрывается сама. `Log` печатает одинаковую строку
  подряд не более трёх раз — иначе сотни «Polling failed» вешают RichTextBox.
- **Состояние Flash** — `Show-FlashInfo` вместо сырого `flash info 0`: сводка одной строкой,
  а при защите — только защищённые секторы диапазонами, с предложением снять её через
  `flash protect N first last off` (чип НЕ стирается, в отличие от `unlock`).
- **Путь к прошивке** переживает перезапуск — `$Base\last.txt`, пишет `Set-FwPath`.

## Константы

| Что | Значение |
|---|---|
| Telnet OpenOCD | `127.0.0.1:4444` (ждём порт, без фиксированных пауз) |
| Адрес по умолчанию | `0x08000000`, размер `0x20000` |
| Частоты SWD | 100 / 480 / 950 / 1800 / 4000 кГц, по умолчанию 950 |
| Мьютекс одного экземпляра | `GD32Flasher_singleton` |
| Признаки успеха | `wrote N bytes`, `verified N bytes`, `dumped N bytes` |

## Грабли (проверенные болью)

1. **Файл `.ps1` — только UTF-8 с BOM.** PowerShell 5.1 читает `.ps1` без BOM как cp1251:
   кириллица разваливается и ломает синтаксис. После любой правки проверять первые байты
   (`efbbbf`). То же касается вспомогательных скриптов и тестов.
2. **Кириллица в путях.** OpenOCD и его Tcl её не переваривают — отсюда работа в
   `%LOCALAPPDATA%` и копия прошивки в `work\fw.bin`. В аргументах `-c` запрещены
   обратные слэши (`\f` = form feed), только прямые — `ConvertTo-TclPath`.
3. **`.bat` не должен передавать путь аргументом.** `powershell -File "%~dp0script.ps1"`
   при кириллице в пути приходит битым. Только `cd /d "%~dp0"` и голое имя файла.
4. **Ошибки OpenOCD не приходят в ответ telnet.** `Error: couldn't open ...` уходит в лог
   процесса. Раньше `Ocd-Run` смотрел только ответ и рапортовал провалившуюся запись как
   успешную. Теперь: лог за время команды + обязательный признак успеха (`$expect`).
5. **Асинхронные сообщения ломают ответы.** OpenOCD шлёт в telnet `external reset detected`
   и т.п. Не выбрать их перед отправкой команды — ответы съедут на команду вперёд.
   `Ocd-Send` дренирует сокет перед записью.
6. **Лог читается на лету и рвёт строки** посреди слова (`Info : [s` + `tm32f1x.cpu]`).
   `Pump-Log` придерживает последнюю строку до перевода строки; `-Final` сбрасывает хвост.
7. **`Error: open failed`** = программатор без драйвера (в диспетчере код 28). Нужен
   STSW-LINK009 или WinUSB (Zadig). После смены драйвера ST-Link **физически переткнуть**,
   иначе он висит фантомом (`Present: False`).
8. **Пробные запуски занимали порт 4444** и следующее «Подключиться» молча отваливалось
   по таймауту. В `Invoke-OpenOcdOnce` серверы отключены (`gdb_port/tcl_port/telnet_port
   disabled`), после Kill — `WaitForExit`, иначе процесс держит ST-Link.
9. **Не ошибки, хоть и выглядят так:** `Warn : STM32 flash size failed` (норма для GD32,
   драйвер не знает его ID), `Adding extra erase range` (конец образа не кратен странице),
   `Error: checksum mismatch - attempting binary compare` (сверка продолжается побайтово).
   Внимание: **в ответ telnet эти строки приходят голыми, без префикса `Warn :`** — фильтр
   по уровню сообщения их не отсекает, нужен список исключений по тексту (`$noise` в
   `Ocd-Run`). На этом уже попались: `flash info 0` считался провалом.
10. **`gdb_port` и компания устарели** — OpenOCD 0.12 отвечает `DEPRECATED! use 'gdb port'`.
    Правильно: `gdb port disabled`, `tcl port disabled`, `telnet port disabled`.
11. **Option bytes применяются только по power-on reset** — после `unlock` снять и подать
    питание, NRST недостаточно.
12. **Аргумент `offset` у `flash write_image` и `verify_image` ПРИБАВЛЯЕТСЯ к адресам
    образа, а не задаёт их.** У `.bin` адресов внутри нет, там offset и есть адрес
    записи. У `.hex`, `.elf`, `.s19` адреса свои: 10.09.2026 к `0x08000000` из hex-файла
    прибавилось `0x08000000` из поля «Адрес», запись ушла на `0x10000000`, где банка нет
    (`Warn : no flash bank found`, `wrote 0 bytes`) — и была объявлена успешной.
    Формат OpenOCD определяет по содержимому, а не по имени, поэтому переименование в
    `fw.bin` ничего не меняет. `Get-ImageOffset` отдаёт offset только для `.bin`.
13. **Перебор конфигов не способен выбрать драйвер.** Замер на живом GD32E103CBT6
    (11.09.2026): `stm32f1x`, `stm32f0x` и `stm32f3x` ОДИНАКОВО отвечают
    `device id = 0x17120410` и `flash size = 128 KiB`. Критерий «первый, кто согласился»
    выбирает случайного из трёх — так и был выбран `stm32f0x`. Решает только `device id`:
    младшие 12 бит = семейство контроллера Flash (`0x410` = medium-density F1, его дают
    и GD32E103, и GD32F330 — `0x21050410`).
14. **`mdw` в разовом запуске молчит.** Значение уходит через `command_print`, до stdout
    не доходит — как и `flash info`. Читать idcode одноразовым `-c "init; mdw ...; shutdown"`
    бесполезно, `device id` берётся из вывода `flash probe 0`.
15. **`shutdown` по telnet НЕ завершает OpenOCD.** Замер 11.09.2026: процесс не выходит
    ни за 800 мс, ни за 10 секунд, закрытие сокета его тоже не трогает. Выход всегда
    делает `Kill`, поэтому `Stop-Session` ждёт лишь 200 мс и убивает.
16. **`VID:PID 0000:0000` / `API v0` — донгл «слетел».** В диспетчере он при этом
    `STM32 STLink`, `Present: True`, и на провода с питанием думать бесполезно. Лечится
    только физическим переподключением. Ловит `Test-ProbeAlive`.
17. **Ноль байт — не успех.** Признаки `wrote/verified/dumped N bytes` требуют
    `[1-9]\d*`: `wrote 0 bytes` означает, что банка для адреса не нашлось.
18. **Дамп из одних `0xFF` — не бэкап.** По адресу без памяти `dump_image` честно
    отдаёт полный размер пустоты и рапортует успех. 10.09.2026 после такого «бэкапа»
    пошло снятие защиты, а оно стирает кристалл при следующей подаче питания —
    восстанавливать было бы уже нечем. Проверяет `Test-DumpHasData`.
19. **Программатор не энумерируется** (`Неизвестное USB-устройство (сбой запроса
    дескриптора)`, `VID_0000&PID_0002`) — питание, а не драйвер: плата-цель сажает донгл.
    Отключить цель от ST-Link и воткнуть его одного. Все порты машины — xHCI (USB 3.x),
    клоны ST-Link V2 с ними дружат плохо, помогает промежуточный хаб USB 2.0.

## Проверка изменений

Железо нужно не всегда: функции достаются из файла через AST и гоняются с заглушками
вместо GUI и telnet. Так проверены `Ocd-Run` (10 кейсов из настоящего лога) и `Pump-Log`
(склейка рваных строк) — см. `z:\tmp\test_ocdrun.ps1`, `z:\tmp\test_pumplog.ps1`.

С железом — `z:\tmp\test_live.ps1`: поднимает настоящую сессию OpenOCD и гоняет те же
функции по живому чипу. Приём, позволяющий проверить запись, ничего не потеряв: сначала
снять дамп, потом прошить чип **этим же дампом** и сверить SHA256 дампов до и после.
Путь записи проверяется целиком, содержимое остаётся прежним.

Синтаксис без запуска GUI:
```powershell
[System.Management.Automation.Language.Parser]::ParseFile('...\GD32Flasher.ps1',[ref]$null,[ref]$errors)
```

## Правила работы

- Правки хирургические, стиль файла (отступы, комментарии по-русски, объясняющие «почему»)
  сохранять.
- Любой новый текст в интерфейсе — ключ в `$Str.RU` и `$Str.EN`.
- Деплой и запуск на боевой машине делает пользователь.
